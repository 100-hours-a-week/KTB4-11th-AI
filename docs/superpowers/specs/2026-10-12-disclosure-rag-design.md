# 공시 원문 기반 RAG

날짜: 2026-10-12
상태: 사용자 검토 대기

## 목적과 확정 요구사항

KOSPI 200 기업의 과거 정기보고서를 저장하고, 요약문 대신 원문에서 추출한 본문을
청킹·임베딩한다. 목표는 기업당 약 5개, 총 약 1,000개 보고서이다. 기업당 보고서의 정확한
구성은 사용자 확인 대기이며, 비정기 공시·감사보고서·증권신고서는 이번 수집 범위에서 제외한다. 기업별 최신 저장 보고서 1~3건을 선택하고 질문에 관련된 청크를 기본 결과로 제공한다.
LLM에 원문 전체를 기본 전달하지 않는다. 요청 시 과거 관련 보고서에서
근거를 추가 검색한다. 원문 재처리, 자료 갱신, 여러 분석 작업에서의 재사용을 지원한다. 사용자 요청에 따라
검색 응답에는 원문 URL이나 인용 위치를 제공하지 않는다. 평가 결과는 Git에서 제외한 로컬 디렉터리에 실행별로 누적한다.

수집 범위의 기본 제안은 현재 KOSPI 200 기업이며, 수집은 기업별 보고서 종류·개수와 기준일로 제한하며, 목록 조회 기간은 설정한다. 현재 구성 종목을 과거 기간에 적용하는 것이므로 역사적 지수 구성원을 복원하는
백테스트 데이터셋으로 주장하지 않는다. 실제 API 수집은 날짜 범위와 설정을 받은 뒤 실행한다.

## 대안과 선택

1. news-preprocessor 확장: 기존 수집을 재사용하지만 긴 공시가 기사 임베딩과 클러스터링에
   섞이고, 원문 아카이브와 뉴스 처리가 결합된다.
2. 전용 수집·색인 서비스와 기존 news-http 확장: 작업 책임을 분리하면서 저장소를 통해
   연결하고, 유일한 읽기 전용 HTTP 진입점을 유지한다. 추천안이다.
3. 독립 RAG HTTP 서버: 독립 배포는 편하지만 기존 HTTP 경계와 운영 표면을 늘린다.

## 구성과 저장 책임

- services/disclosure-collector: OpenDART 목록과 문서 수집, 원본 보관, 본문 추출.
- services/disclosure-indexer: 미처리 본문 청킹, 임베딩, 색인 버전 관리, 로컬 평가 실행.
- services/news-http: 공시 목록과 근거를 반환하는 읽기 전용 검색 API.

수집·색인은 각각 한 번 실행 후 종료한다. 서비스마다 환경변수 접두사를 가진 settings.py와
JSON 로깅을 둔다. 마이그레이션은 별도 작업으로 수행한다.

기존 news-preprocessor의 짧은 공시 뉴스 흐름은 유지한다. 새 collector는 RAG 원문
아카이브를 소유한다. 기존 articles의 접수번호와 대응 관계를 보존한다. 두 파이프라인이
동일 문서를 내려받을 수 있다는 초기 한계는 명시한다. 공통 아카이브를 기존 뉴스 흐름도
읽게 하는 전환은 원문 파이프라인이 검증된 뒤 별도 변경으로 진행한다.

원본 ZIP과 그 안의 XML/HTML 문서 전체는 공유 가능한 영속 볼륨에 저장한다. 로컬 경로가
DB에 절대 경로로 고정되지 않도록 설정된 저장 루트 기준의 상대 키와 해시를 기록한다.
개발 기본 저장 위치는 .local/disclosure-rag/archive/이며 운영에서는 영속 볼륨을 마운트한다.
원본에서 재현 가능한 본문, 섹션, 표 텍스트를 PostgreSQL에 저장한다. 첫 구현에서 별도
오브젝트 스토리지는 도입하지 않는다.

## 데이터 모델

- disclosures: 접수번호 고유 키, 종목코드·기업코드, 제목, 접수일, 원문 URL, 원본 메타데이터,
  문서 취득 상태, 오류·재시도 횟수.
- disclosure_documents: 공시·원본 파일 키, 원본 해시, 추출기 버전, 추출 본문·섹션,
  처리 상태. 원본과 추출본을 구분하고 원본 변경 시 이전 버전을 보존한다.
- disclosure_chunks: 문서 버전, 청크 순서, 섹션 경로, 추출 본문 내 시작·끝 위치, 텍스트,
  청킹 버전, 임베딩 모델·차원·색인 버전, 벡터.
- 수집 진행 상태: 기업·날짜 구간별 완료 여부, 재시작 가능한 체크포인트.

기사 테이블의 vector(2000) 설정을 변경하지 않는다. 공시 벡터 차원은 전용 스키마에서
명시하고 설정과 일치 여부를 검증한다. 다른 모델의 벡터를 같은 색인에서 비교하지 않는다.
모델·차원 변경에는 새 색인 버전과 필요한 스키마 변경을 사용한다.

## 수집과 원문 추출

공시 목록 API의 날짜 구간을 나누어 페이지를 끝까지 수집한다. 정기보고서 유형만 선택하고 기업별 목표 개수를 적용한다. 정확한 보고서 구성은
확인 후 고정한다. 접수번호로 중복을 방지하고 문서 취득 실패는 재시도 대상으로 남긴다.
정정공시는 원 공시를 덮어쓰지 않고 별도 접수번호로 보존한다. 연계가 확실할 때만 관계를
기록하고 제목만으로 정정 관계를 확정하지 않는다.

BeautifulSoup으로 XML/HTML을 해석하고 제목·단락·표의 순서를 유지한다. 표는 행·열 경계를
보존한 텍스트로 제공하고 단위·기간·제목을 함께 남긴다. 기존 파서처럼 모든 텍스트를 하나의
공백 문자열로 평탄화하지 않는다. ZIP 안의 첫 파일만 처리하지 않고 문서별 출처를 보존한다.

문서 없음, 지원하지 않는 첨부 형식, 파싱 실패, 표 추출 한계를 상태로 구분한다. 원문이 없는
공시는 목록에 표시하되 본문 근거를 만든 것처럼 반환하지 않는다. PDF/OCR 처리는 첫 단계
범위 밖이며 해당 첨부가 빠졌음을 표시한다. API 제한·네트워크 오류에는 제한된 재시도와
요청 간격을 적용한다. API 키를 로그나 평가 기록에 남기지 않는다.

## 청킹과 색인

섹션과 단락 경계를 우선하고 임베딩 모델 입력 한도를 지키며 긴 구간을 분할한다. 짧은 공시는
본문 전체를 한 청크로 유지할 수 있다. 표 분할 시 제목·열 이름·단위를 반복해 문맥을 보존한다.
원문을 요약해서 대체하지 않는다. 인용 위치는 추출 본문 기준이며 원본 페이지 번호를 임의로
만들지 않는다.

본문·추출기·청킹·모델 버전이 같으면 재임베딩하지 않는다. 새 색인이 완성되기 전에는 이전
완성 색인을 유지하고, 실패한 작업은 재시작할 수 있게 한다.

## 검색 계약

GET /stocks/{stock_code}/disclosures

- limit: 1~3, 기본 3. 청크 개수가 아니라 공시 문서 개수이다.
- as_of: 선택 기준일. 제공하지 않으면 현재 날짜를 기준으로 한다.
- 접수일 내림차순, 동일 날짜에서는 접수번호 내림차순으로 결정적으로 정렬한다.
- 최신 문서가 미색인·원문 없음이어도 목록에서 숨기고 더 오래된 문서로 대체하지 않는다.

POST /stocks/{stock_code}/disclosures/search

- query: 필수 질문.
- latest_limit: 1~3, 기본 3.
- include_history: 기본 false.
- as_of: 선택 기준일, 공시일이 이를 넘는 문서는 모든 검색에서 제외한다.
- history_start: 선택 과거 검색 시작일.
- top_k: 기본 6, 최대 20. 최신 문서 근거와 과거 근거 각각의 청크 예산이다.
- history_limit: 기본 3, 최대 10. 추가 과거 공시 문서 개수 제한이다.

먼저 기업과 기준일로 최신 문서를 선택하고 해당 문서 안에서 관련 청크를 검색한다.
include_history=true이면 최신 문서를 제외한 같은 기업의 과거 공시에서도 관련 근거를 찾는다.
최신 목록과 최신 근거, 추가 과거 근거를 구분해 반환하며 관련 근거가 없는 문서를 억지로
채우지 않는다. 기업 이름의 의미 유사도로 기업을 결정하지 않는다.

초기 검색 기준선은 기업·날짜 필터와 정확한 코사인 검색이다. 좁은 후보 집합에서 정확 검색을
사용해 근거 누락을 측정한다. 키워드 검색·혼합 검색·재정렬은 같은 평가 집합에서 비교한 뒤
개선이 확인되면 도입한다. 초기 버전에서 한국어 full-text 검색 품질을 가정하지 않는다.

검색 시 질문 임베딩은 기존 OpenAI 호환 엔드포인트를 사용한다. news-http는 읽기 전용을
유지하고 색인 상태를 변경하지 않는다. 요청 제한·타임아웃과 모델 버전 일치를 검증한다.
검색 응답에는 보고서 제목·종류·보고 기간, 종목코드, 접수일, 관련 청크 텍스트, 검색 점수·방식,
원문·색인 상태를 담는다. 원문 URL, 접수번호 기반 출처 표기, 문서 키, 섹션 경로와 본문 위치는
응답에서 제외한다. 접수번호·문서 해시·본문 위치는 중복 제거와 내부 평가를 위해 저장한다.

첫 단계는 근거 검색까지다. LLM 답변 생성이나 portfolio-builder 도구 연결은 이후 독립 작업이다.
검색 기능은 투자 판단 정확도를 보장하지 않는다.

## 로컬 발전 기록

.local/disclosure-rag/ 전체를 .gitignore와 .dockerignore에서 제외한다. 원본, 평가 데이터,
실행 결과, 비교 보고서를 이 경로에 둔다. 코드·설계·테스트는 일반 변경으로 남기되 push하지 않는다.

평가 실행은 고유 실행 ID로 기록하고 이전 결과를 덮어쓰지 않는다. manifest에는 코드 커밋과
미커밋 변경 해시, 문서 집합 해시, 평가 질문 집합 해시, 추출·청킹·모델·검색 설정, 실행 환경을
기록한다. 동일 질문·자료로 기업·날짜 조회 후 전체 본문 제공, 벡터 검색, 후속 개선을 비교한다.

측정 항목은 정답 근거 Recall@k, 순위 지표, 최신 문서 선택 정확성, 기업·기준일 필터 위반,
내부 청크 위치 일치, 검색 지연 p50/p95, 인덱싱 시간, 입력 토큰과 제공된 가격 기준의 추정 비용이다.
청크와 문서 단위 지표를 구분한다. 실제 투자 수익률 개선으로 해석하지 않는다.

실측 토큰과 추정값을 구분하고 가격표·토크나이저가 없으면 비용·토큰을 미측정으로 남긴다.
검색 평가는 답변 정확도 평가와 구분한다. 수작업으로 정답 접수번호·근거 구간을 검토한 질문
집합이 있어야 품질 개선을 주장한다. 실제 데이터·API 접근이 없으면 테스트 결과만 기록하며
실제 성능 개선을 주장하지 않는다.

## 검증과 배포

테스트는 긴 문서·여러 파일·표·정정·문서 없음·중복·재시작, 청크 위치·전체 본문 보존,
색인 버전 전환·실패, 기업·기준일 제한, 최신 문서 개수, 과거 옵션·중복 제거를 검증한다.
DB 통합 테스트는 KTB_TEST_POSTGRES_DSN을 사용하고 개발 DB를 truncate하지 않는다.
평가 결과 경로가 Git과 Docker 컨텍스트에서 제외되는지도 검증한다.

uv workspace 구성, 서비스별 Dockerfile, 단일 운영 이미지, requirements exports, Compose,
환경변수 예제, README, AGENTS.md를 함께 갱신한다. 외부 서비스 호출 없이 동작하는 단위
테스트와 별도 테스트 DB 통합 테스트를 구분하고 실제 API 평가는 명시적으로 실행한다.

## 구현 순서

1. 스키마와 원문 수집·보존·재시작.
2. 본문 추출·청킹·임베딩 및 색인 버전 관리.
3. news-http의 최신 목록·근거 검색과 과거 옵션.
4. 로컬 평가·비교 보고서와 운영 구성.

이 문서는 설계 검토 대상이며 구현 계획과 제품 코드는 아직 작성하지 않는다.

## 2026-10-12 사용자 수정

- 최신 1~3건은 보고서 선택 개수이며, 검색 응답은 관련 청크이다.
- KOSPI 200 기업당 약 5개 정기보고서, 총 약 1,000개를 목표로 범위를 좁힌다.
- OpenDART 정기보고서는 1분기·반기·3분기·사업보고서로 연간 4개이므로 구성 확인이 필요하다.
- 출처·인용 위치 제공은 제거한다. 내부 식별자는 중복 방지와 평가를 위해 유지한다.
- 별도 관리형 worktree에서 구현하며 원래 checkout의 제품 코드는 변경하지 않는다.
