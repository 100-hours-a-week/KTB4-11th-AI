# Participant portfolio rebalancing (#514)

The rebalancer retains its existing pricing, target weights, cancellation publication, and Order FIFO payload. It selects a portfolio for each active account before publishing any cancellation. Participants use only portfolios linked to their participant ID and owning user ID; the latest linked portfolio must be ready. Missing mappings and unready portfolios skip that account without falling back to a common or older portfolio. Participant exit reasons come only from that same ownership history, including portfolios shared by multiple participants.

Common selection and historical exit reasons exclude every portfolio linked in `competition_portfolios`, even while participant execution is disabled. On a database without #484's competition tables, common operation remains compatible and participant selection returns no portfolio. This change adds no migrations.

`PORTFOLIO_REBALANCER_COMPETITION_ENABLED=false` is the deployment default in local and production Compose. It preserves common-account operation for Backend snapshots that omit `participant_id`, while always skipping accounts with a positive participant ID. Before enabling it, deploy #484's `competition_participants` and `competition_portfolios` schema and generation path, then deploy the Backend account snapshot contract: every account must include `participant_id`, with explicit null for common accounts or a positive strict integer for competition accounts. The currently deployed Backend does not yet emit this field.

After those prerequisites, set `PORTFOLIO_REBALANCER_COMPETITION_ENABLED=true` and recreate the scheduled rebalancer container. With the flag enabled, accounts missing the field are skipped before cancellation or placement. Invalid IDs reject the snapshot before publication. No account ID, investment profile, agent ID, or user ID is treated as an inferred participant mapping. Reverting the flag disables competition execution; explicit participant accounts remain skipped.

The initial Backend snapshot is fetched once. Every duplicate account ID is excluded across the complete snapshot, including identical duplicates and conflicts between common and competition accounts. A participant assigned to multiple active accounts also excludes every affected mapping. These checks apply before any cancellation or placement in both modes; unrelated accounts continue. A missing or unready common portfolio cannot stop ready participant accounts when enabled. Resolved selections are cached per user and participant. Quotes cover every selected target and held stock. Selection, cancellation, and placement logs carry user, account, participant, and portfolio IDs; no new fields enter the Backend order payload. Partial cancellation publication still prevents all replacements for that account.

Verification covers legacy default behavior, strict identity parsing, enabled rollout safeguards, mixed common and participant accounts, cache and quote aggregation, SQL owner isolation, shared history, and latest-unready behavior. Competition SQL tests skip when #484 schema is absent; they are also run against a separately migrated test database.
